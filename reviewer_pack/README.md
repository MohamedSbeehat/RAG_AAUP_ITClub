# حزمة تجربة CampusIQ للمقيّمين

هذه **جامعة وهمية** وبيانات عامة مصنوعة للاختبار، وليست لوائح AAUP أو معلومات جامعة حقيقية. الغرض هو تجربة قدرة RAG على قراءة الملفات والاستشهاد بها، دون بيانات طلاب أو مفاتيح سرية.

## التشغيل والتجربة اليدوية

1. من جذر المشروع شغّل `start-company.cmd` على Windows أو `sh start-company.sh` على Linux. التنزيل الأول للاعتماديات ونموذج التضمين يحتاج إنترنت ومساحة على القرص.
2. لتوليد الإجابات، أضف مفتاحك إلى `GEMINI_API_KEY` في `.env` محلياً واختر نموذجاً متاحاً لحسابك. لا ترفع `.env` إلى GitHub. بدون مزود يمكنك تجربة **المقتطفات فقط**؛ هذا لا يختبر التوليد أو الامتناع.
3. افتح <http://127.0.0.1:8000> وأنشئ **حساب شركة تجريبي جديداً**، بنوع «مراجع أكاديمية».
4. في Documents ارفع **الملفات الخمسة الموجودة داخل `reviewer_pack/documents/` فقط**. انتظر انتهاء الفهرسة. لا تضف مراجع AAUP أو ملفات أخرى لهذا الحساب أثناء هذه التجربة.
5. في Chat اختر «كل ملفات شركتي» و«إجابة بالمساعد». ابدأ محادثة جديدة لكل سؤال مستقل. افتح رابط المصدر للتحقق من اسم الملف وصفحة PDF.

**لا ترفع `cases.json` أو التقرير أو هذا الدليل إلى قاعدة المعرفة**: تحتوي هذه الملفات على الإجابات المتوقعة، ورفعها يفسد الاختبار. ارفع محتويات مجلد `documents` فقط، ولا ترفع ZIP مباشرة.

## أمثلة مثل معايير التقييم

| النوع | جرّب هذا السؤال | المتوقع من ملفات التجربة |
| --- | --- | --- |
| سؤال مباشر | ما الحد الأدنى لنسبة الحضور في المادة؟ | 75% مع مصدر الحضور، صفحة 1. |
| لهجة فلسطينية | شو بصير إذا غبت أكتر من المسموح وما معي عذر مقبول؟ | تجاوز 25%: حرمان من النهائي وصفر، بإجابة عربية بسيطة ومصدر. |
| قراءة جدول | كم ساعة معتمدة لمادة البرمجة المتقدمة CS102؟ | 4 ساعات من صف CS102، لا 3 من الصف المجاور. |
| جمع مستندين | معدلي 2.1 وأنا سنة ثالثة، كم ساعة بقدر أسجل؟ | حد المعدل 15 وسقف السنة 18؛ الأقل 15، مع الاستشهاد بالملفين. |
| متابعة | بعد السؤال السابق: واذا صار معدلي ٣٫٧؟ | يتذكر السنة الثالثة؛ الأقل بين 21 و18 = 18. |
| غير موجود | متى موعد امتحان الخوارزميات؟ | يقول إن الموعد غير موجود ويحيل لشعبة الامتحانات دون اختراع تاريخ. |
| خارج النطاق | اكتبلي قصيدة عن الجامعة | يرفض ويشرح نطاق مساعد المستندات؛ لا ينشئ قصيدة. |

اللغة الفلسطينية مدخلاً، والإجابة العربية البسيطة مقبولة؛ لا يشترط تقليد اللهجة. تشمل الحزمة «قديش»، «بقدر»، «هسا»، «عالأقل»، «إلها»، والكتابة دون همزة والأرقام العربية.

## سلاسل المتابعة

استخدم **محادثة جديدة** لكل سلسلة، مع إبقاء أسئلتها في المحادثة نفسها:

- `M01 → F01 → F02`: معدل 2.1 وسنة ثالثة =15، ثم معدل 3.7 =18، ثم سنة رابعة =21.
- `T01 → F05 → F06`: CS102 أربع ساعات، ثم «وشو متطلبها السابق؟» =CS101، ثم «وكم ساعة إلها؟» =4. يختبر بقاء مرجع الضمير عبر أكثر من رسالة.
- `D03 → F03`: معدل 1.9 حسب المعدل وحده =12، ثم «واذا كان معدلي أعلى من ذلك، قديش بقدر أسجل نهائياً؟» يطلب المعدل الرقمي والسنة ولا يخمن.
- `D01 → F04`: بعد سؤال الحضور، غياب 30% دون عذر مقبول يعني الحرمان والصفر.

كل الأسئلة الـ42 مع المتوقع ونوعها موجودة في [cases.json](./cases.json). ترتيب الحالات هناك مرتبط بمعرّفات المحادثات؛ سكربت الاختبار يدير كل سلسلة على حدة.

## اختبار آلي قابل للإعادة

من جذر المشروع:

```powershell
uv sync --locked --group dev
uv run pytest -q
uv run python scripts/evaluate_reviewer_pack.py --mode retrieval --output outputs/reviewer-retrieval
uv run python scripts/evaluate_reviewer_pack.py --mode live --profile smoke --output outputs/reviewer-smoke
```

- `retrieval`: تضمينات multilingual-e5 وQdrant فعليان، دون استدعاء LLM. يقيس وجود ملفات الأدلة للحالات الـ29 القابلة للإجابة؛ لا يقيس 12 حالة امتناع أو حالة طلب توضيح.
- `live --profile smoke`: يستدعي المزود الحقيقي لـ16 حالة تغطي الأنواع السبعة، بما فيها الإنجليزية والفلسطينية والمتابعة عبر الضمائر. `--profile full` يشغّل الحالات الـ42. يحتاج مفتاحاً صالحاً وحصة متاحة وقد يستهلك رصيد المزود. حصة 20 طلباً يومياً لا تكفي للجولة الكاملة؛ المجموعة القصيرة تحتاج 16 طلباً متاحاً على الأقل. يستغرق عدة دقائق ويحترم حد الأسئلة.
- لاختيار سؤال واحد جرّب `--mode live --case-ids F06`. يضيف السكربت تلقائياً T01 وF05 قبله لتوفير سياق المتابعة؛ هذه ثلاثة طلبات وليست طلباً واحداً. تبقى الأسئلة المتوقعة خارج قاعدة المعرفة.
- افتراضياً يعمل السكربت عبر FastAPI TestClient وبيانات مؤقتة مستقلة، ولا يحتاج إيقاف التطبيق. النموذج والتضمينات حقيقيان؛ TestClient لا يختبر اتصال المتصفح بالشبكة.
- لفحص خادم HTTP يعمل فعلياً: أضف `--base-url http://127.0.0.1:8000`. ينشئ السكربت حسابين عشوائيين خاصين بهذه الجولة، ثم يزيل ملفاتهما ويبطل جلستيهما؛ تبقى حسابات الاختبار وسجلات التدقيق في الخادم. لا يحذف حساباً أو ملفات موجودة مسبقاً.
- تُحفظ الإجابات والفحوص والأزمنة والمصادر في `.json` و`.md` داخل `outputs/`. يرجع السكربت رمز خروج 1 عند فشل أو خطأ؛ لا يحوّل خطأ المزود إلى نجاح.
- لا يضع السكربت الأسئلة المتوقعة داخل RAG ولا يحاكي Gemini أو التضمينات.

## كيف تقرأ النتيجة؟

الفحوص الآلية تتحقق من اللغة، أنماط حقائق متوقعة، وجود مصادر الملفات المطلوبة، معرّفات الاستشهادات، صفحة PDF، ومطابقة الملف المحلي لبصمته، وصيغ الامتناع وطلب التوضيح. وتفحص أيضاً الرفع والتكرار وعزل حسابين والإزالة وإبطال الجلسة.

**هذه فحوص محدودة وليست إثباتاً دلالياً أن كل جملة صحيحة.** راجع النص الفعلي مقابل «المتوقع»، خصوصاً النتيجة النهائية في مسائل المعدل وسقف السنة؛ مجرد وجود الرقم الصحيح في الشرح لا يثبت أنه النتيجة النهائية. فحص اللغة لا يصادق وحده على جودة فهم اللهجة. نتائج النسخة المقاسة موثقة في [reports](./reports/).

ملف الحضور يحتوي النص العربي المنطقي المرفق، بنفس آلية تصدير مراجع التطبيق. ملف جدول المساقات PDF نصي عادي **دون مرفق إجابات أو نص خاص**، ويختبر استخراج جدول PDF الحقيقي. لا تمثل الحزمة اختبار OCR على صور مجهولة.

## إعادة بناء مستندات الاختبار

المستندات الخمسة موجودة في GitHub ولا تحتاج بناءها. عند تعديلها عمداً شغّل:

```powershell
uv run python scripts/build_reviewer_documents.py
```

ينتج PDF تحت `output/pdf/reviewer_pack/` وينسخه إلى `reviewer_pack/documents/` ويحدث البصمات في `manifest.json`. راجع الصفحتين بصرياً، ثم راجع المتوقع في `cases.json` وأعد الاختبارات. لا تغيّر المتوقع لمجرد جعل إجابة خاطئة تنجح.
