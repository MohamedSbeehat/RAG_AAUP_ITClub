# مساحة RAG للمستندات — الشركات وAAUP

مساعد عربي/إنجليزي يجيب من ملفات المؤسسة مع إحالات إلى المستند الأصلي. يدعم وضع شركة مستقلاً وملف إعداد AAUP الأكاديمي، مع فهرس منفصل لكل مساحة تشغيل.

## تشغيل نسخة الشركة

على Windows، شغّل [start-company.cmd](./start-company.cmd). على Linux استخدم `sh start-company.sh`. تحتاج أداة `uv`؛ ينشئ المشغّل `.env` من [.env.company.example](./.env.company.example) إذا لم يوجد، ثم يثبت الاعتماديات المقفلة ويشغّل الخادم. تنزيل Python والاعتماديات ونموذج التضمين لأول مرة يتطلب اتصال إنترنت ومساحة كافية على القرص. يُحافظ على `.env` الموجود ولا يُستبدل.

1. أضف مفتاح الشركة إلى `GEMINI_API_KEY` في `.env`، واختر نموذجاً متاحاً للحساب. النموذج الذي نجح في التحقق الحالي هو `gemini-3.5-flash`.
2. ضع الملفات في **`documents/`** داخل المشروع، ويمكن تنظيمها في مجلدات أقسام فرعية.
3. افتح <http://127.0.0.1:8000>. تظهر أعداد المستندات والمقاطع وحالة الفهرسة وقائمة الملفات.
4. تُفهرس الإضافات والتعديلات تلقائياً كل **15 ثانية**. يمكن رفع الملفات أو الضغط على «مزامنة الآن» من الواجهة أيضاً.
5. اسأل بالعربية أو الإنجليزية؛ افتح المستند من بطاقة المصدر، مع الانتقال إلى الصفحة عند توفر رقم صفحة PDF.

الأنواع المدعومة: PDF النصي، DOCX، XLSX، TXT، Markdown. حد الرفع الافتراضي **25 MB لكل ملف** وقابل للتغيير. ملفات PDF المصوّرة تحتاج OCR مسبقاً. الملف الذي يتغير أثناء قراءته لا يُعتمد حتى فحص لاحق؛ تظهر أخطاء الاستخراج والفهرسة في الواجهة.

حذف ملف من المجلد يزيل مقاطعه من SQLite وQdrant في الفحص التالي، عند `REMOVE_DELETED_DOCUMENTS=true`. لا يحذف التطبيق ملفاتك الأصلية أثناء المزامنة. إذا تعذر الوصول إلى مجلد المستندات كله، يُحافظ على الفهرس وتظهر رسالة خطأ. الأسماء المتطابقة في مجلدات أقسام مختلفة لا تُعامل كنسخ من المستند نفسه.

إعدادات وضع الشركة الأساسية:

```dotenv
KNOWLEDGE_MODE=organization
ORGANIZATION_NAME=Company
ASSISTANT_NAME="مساعد ملفات الشركة"
RAW_DIR=documents
DATABASE_PATH=indexes/company.sqlite3
QDRANT_COLLECTION=company_chunks
LLM_PROVIDER=gemini
GEMINI_MODEL=gemini-3.5-flash
REFRESH_INTERVAL_SECONDS=15
```

لا تختلط ملفات AAUP مع مساحة الشركة: يحتفظ الوضع الأكاديمي بمجلد `data/raw/` وقاعدته `indexes/rag.sqlite3`، بينما تستخدم الشركة المسارات أعلاه. لا تُنسخ بيانات الجامعة إلى مجلد الشركة تلقائياً. لا يحتفظ مجلد `documents/` الافتراضي ببيانات تجريبية أو سياسات مصطنعة.

### إعداد مؤسسة أخرى وحماية الوصول

هذه نسخة **لمؤسسة واحدة لكل تشغيل**. خصص مجلد ملفات وقاعدة SQLite ومسار Qdrant أو مجموعة مستقلة لكل مؤسسة. ليست منصة اشتراكات متعددة المؤسسات أو نظام صلاحيات منفصلة لكل موظف. إعداد `APP_USERNAME` و`APP_PASSWORD` يحمي الواجهة وجميع مسارات API بمصادقة HTTP Basic مشتركة للمساحة.

التشغيل الافتراضي مقيد بالجهاز المحلي. يرفض أمر `serve` الربط بعنوان شبكة خارجي دون `APP_PASSWORD`. عند نشره على شبكة مؤسسة، اضبط كلمة مرور قوية واستخدم HTTPS عبر وكيل عكسي؛ لا تضعه مكشوفاً على الإنترنت بإعداد التشغيل المحلي. إعدادات العلامة والمجلد وقاعدة البيانات والحماية تُقرأ عند بدء التشغيل، بينما إعداد التوليد يُعاد تحميله عند الطلب.

تُرسل إلى Gemini مقتطفات الوثائق وسياق المحادثة اللازمان للسؤال. استخدم فقط مواد تسمح المؤسسة بإرسالها للمزود؛ يمكن اختيار Ollama عند الحاجة إلى توليد محلي. لا تُدرج مفاتيح API أو ملفات الشركة أو الفهارس في Git أو في حزمة تسليم عامة.

فحص الإعداد وتشغيل اختبار توليد فعلي صغير:

```powershell
uv run rag-aaup doctor
uv run rag-aaup doctor --check-provider
```

يعرض الفحص حالة الإعداد دون كشف المفاتيح. يتطلب الاختبار الثاني اتصالاً بالمزود ويستهلك طلب توليد صغيراً. إذا كان الخادم يعمل بوضع Qdrant المحلي، نفّذ إعادة الفهرسة من الواجهة بدلاً من فتح الفهرس في عملية ثانية.

### تحقق نسخة الشركة

بتاريخ **2026-11-07** نجحت **38 حالة اختبار**، وفحص حزمة Python أثبت تضمين الواجهة. نجحت دورة HTTP فعلية: إضافة ملف تجريبي إلى المجلد، فهرسته دون استدعاء يدوي، إجابة عربية من Gemini بالرقم الصحيح وإحالة إلى الملف، فتح المستند الأصلي، ثم اكتشاف تعديل الملف وحذفه تلقائياً. أزيل الملف التجريبي بعد الفحص، وأعادت المساحة الفارغة امتناعاً واضحاً. تُحجب الإحالات غير الموجودة في الاسترجاع، وتتحول الإجابة الخالية من الاستشهادات إلى امتناع آمن. بقي تقييم AAUP المستقل ناجحاً **7/7**.

## الوضع الأكاديمي AAUP

استخدم [.env.example](./.env.example) كمرجع لهذا الوضع. يهدف إلى إجابات مرتبطة بمصدر قابل للتحقق، لا إلى توليد سياسات جامعية من الذاكرة.

> **تنبيه:** لا تضعوا بيانات شخصية أو ملفات سرية في النظام. ملف الاختبار المرفق مُلخّص من مصادر AAUP الرسمية، وليس لائحة رسمية. المستندات التي تصلح للمسابقة يجب أن تأتي من اللجنة أو من مصدر عام موثوق، مع توثيق المصدر.

## المتطلبات

- Windows 10/11 أو Linux.
- Python 3.13 (الإصدار المحدد في `.python-version`).
- `uv` لإدارة بيئة المشروع.
- مساحة قرص لتنزيل نموذج التضمين متعدد اللغات أول مرة. يعمل التضمين محلياً؛ لا يحتاج مفتاح API.
- لتوليد الإجابات: مفتاح Gemini من الخطة المجانية، أو Ollama مع نموذج محلي. حدود الخطط المجانية وتوفرها تتغير؛ Ollama لا يحتاج API key لكنه يحتاج تنزيل النموذج.

## التثبيت والتشغيل على Windows

```powershell
winget install --id astral-sh.uv
uv sync --group dev
Copy-Item .env.example .env
uv run rag-aaup serve
```

افتح <http://127.0.0.1:8000>. تُتاح واجهة API التفاعلية على <http://127.0.0.1:8000/docs>.

### إعداد توليد الإجابات المجاني

**Gemini (اختياري):** أنشئ مفتاحاً من Google AI Studio وأضفه إلى `.env` في `GEMINI_API_KEY`. لا تضع المفتاح في GitHub أو في الواجهة الأمامية.

**Ollama المحلي (بدون مفتاح):**

```powershell
winget install --id Ollama.Ollama
ollama pull qwen2.5:3b
```

عند `LLM_PROVIDER=auto` يحاول النظام Gemini عند وجود مفتاح، ثم Ollama عند فشل خدمة Gemini. إذا لم يكن أي مزود متاحاً، يرجع النظام خطأ واضحاً بدلاً من إجابة وهمية. ويمكن ضبط `LLM_PROVIDER` إلى `gemini` أو `ollama`.

عند اختيار Gemini دون مفتاح، تعرض الواجهة **وضع المصادر فقط** وتتيح البحث عن مقتطفات المستندات دون استدعاء LLM. هذه المقتطفات ليست إجابة مولّدة أو تأكيداً بأن كل نتيجة تدعم السؤال. لتفعيل الإجابات، أضف `GEMINI_API_KEY` إلى `.env` واحفظ الملف؛ تُقرأ إعدادات التوليد عند الإرسال دون إعادة تشغيل الخادم، ولا يُرسل المفتاح إلى الواجهة. تعرض `/api/status` حالة الإعداد فقط، ولا تتحقق من صلاحية المفتاح أو الحصة لدى المزود.

تُضبط مهلة اتصال المزود عبر `LLM_TIMEOUT_SECONDS=40`، مع مهلة إجمالية للطلب وزر يعود للعمل بعد الفشل أو انتهاء المهلة. تمنع الواجهة الإرسال المكرر أثناء الطلب. يمكن اختيار البحث في المصادر يدوياً حتى عند تهيئة Gemini. يستخدم نموذج التضمين النسخة المحلية المخبأة أولاً لتجنب اتصال تنزيل غير ضروري عند بدء البحث.

## إضافة المستندات وتحديثها

انسخ ملفات الجامعة إلى `data/raw/`، أو ارفعها عبر واجهة `/docs` باستخدام `POST /api/documents`. الأنواع الحالية: PDF النصي، DOCX، XLSX، TXT، وMarkdown. ملفات PDF المصوّرة التي لا تحتوي طبقة نص تحتاج OCR، وهو غير مفعّل في هذه النسخة.

يتضمن المستودع ملف اختبار واحداً [AAUP_Official_Test_Corpus_2026-11-07.md](./data/raw/AAUP_Official_Test_Corpus_2026-11-07.md)، وهو ملخص مُعاد الصياغة من لوائح وصفحات AAUP الرسمية مع روابط المصادر وتاريخ التحقق. كما تم تنزيل نسخة PDF الرسمية محلياً للاختبار، لكنها مستثناة من Git؛ لا يُرفع ملف المصدر الأصلي دون مراجعة حقوق النشر وسياسة اللجنة.

يفحص التطبيق مجلد `data/raw/` عند التشغيل، بعد الرفع، وكل 15 ثانية افتراضياً. ويمكن فرض فحص فوري عندما يكون الخادم متوقفاً:

```powershell
uv run rag-aaup index
```

يخزن **Qdrant** التضمينات وينفذ البحث الدلالي بمقياس cosine. يحتفظ SQLite ببصمة كل ملف والمقاطع والبيانات الوصفية والمحادثات وفهرس FTS5، وبنسخة من التضمينات للترحيل والتعافي من فشل المزامنة. لا يستخدم الاسترجاع حساب تشابه NumPy أو مسح تضمينات SQLite لكل سؤال. الملفات التي لم تتغير لا يعاد تضمينها؛ والملف المحدّث يعاد فهرسته. لا تُرسل التضمينات إلى خدمة توليد الإجابات.

### قاعدة المتجهات والترحيل

الوضع الافتراضي هو Qdrant محلي دائم على القرص، دون خادم منفصل. يُشتق مساره من `DATABASE_PATH`: مثلاً `indexes/rag.sqlite3` يستخدم `indexes/rag.qdrant/`. ويمكن تغييره عبر `QDRANT_PATH`.

لترحيل الفهرس السابق، أوقف التطبيق القديم ثم شغّل:

```powershell
uv sync --group dev
uv run rag-aaup index
uv run python scripts/evaluate_retrieval.py
uv run rag-aaup serve
```

تُضاف معلومات الترحيل تلقائياً إلى SQLite، وتُنقل التضمينات المخزنة إلى Qdrant دون إعادة حسابها. تبقى الوثائق والمحادثات الحالية محفوظة. عند تحديث ملف، تُحدّث المتجهات المتغيرة وتُحذف المقاطع المستبدلة. إذا فشلت الكتابة إلى Qdrant، يُبلّغ أمر الفهرسة عن الخطأ وينتهي برمز فشل؛ وتُعاد محاولة المزامنة قبل البحث التالي أو بعد إعادة التشغيل. يظهر تعطل Qdrant في `/api/ask` كخطأ `503`، ولا يُعامل على أنه غياب دليل أكاديمي.

**قيود الوضع المحلي:** استخدم عملية تطبيق واحدة. أثناء تشغيل `serve`، نفّذ إعادة الفهرسة عبر `POST /api/reindex` أو انتظر المزامنة الدورية؛ أوقفه قبل تشغيل أمر `index` أو سكربت التقييم في عملية أخرى على المجلد نفسه. يُغلق التطبيق Qdrant عند التوقف لتحرير قفل الملفات.

للاستخدام مع خادم Qdrant مُجهّز، اضبط:

```dotenv
QDRANT_URL=http://127.0.0.1:6333
QDRANT_API_KEY=
QDRANT_COLLECTION=academic_chunks
QDRANT_TIMEOUT_SECONDS=30
```

عند ضبط `QDRANT_URL`، يُتجاهل المسار المحلي وتُرسل التضمينات والبيانات الوصفية للمقاطع إلى الخادم المحدد؛ اختر خادماً موثوقاً. تبقى بيانات SQLite مطلوبة. لكل قاعدة SQLite معرّف ثابت يُستخدم لتصفية نقاطها داخل مجموعة Qdrant المشتركة؛ وهذا فصل لفهارس قواعد البيانات، وليس تطبيقاً كاملاً لعزل مستخدمي SaaS. يجب ألا تتشارك نماذج ذات أبعاد مختلفة المجموعة نفسها. عند تغيير نموذج التضمين، استخدم قاعدة SQLite ومجموعة Qdrant جديدتين وأعد الفهرسة الكاملة من الملفات.

يدعم العميل الرسمي النمطين [المحلي والخادم](https://github.com/qdrant/qdrant-client#local-mode). جرى التحقق في هذه الجولة من النمط المحلي الدائم؛ الاتصال بخادم خارجي يحتاج إعداد الخادم واختباره في بيئة النشر.

### نسخ المستندات

احتفظوا بنسخ السياسات ولا تستبدلوا الأقدم عند إضافة إصدار جديد. استخدموا اسماً ثابتاً مع سنة أو رقم إصدار في النهاية، مثل:

```text
data/raw/Student_Guide_2025.pdf
data/raw/Student_Guide_2026.pdf
```

تُجمع النسخ ذات الاسم الأساسي نفسه، وتُفضّل النسخة ذات السنة/رقم الإصدار الأعلى. عند عدم توفر مقطع ملائم في النسخة الأحدث، يمكن الاسترجاع من النسخ الأقدم وتظهر بوضوح في المصدر على أنها مرجع احتياطي. للمستندات التي تحمل أسماء غير متسقة، وحّدوا الاسم الأساسي قبل الفهرسة؛ لا يُستنتج تطابق النسخ من تشابه محتواها.

## كيف يعمل

```text
PDF / DOCX / XLSX / TXT / Markdown
        ↓
استخراج النص والصفحة أو القسم
        ↓
تقطيع متداخل + تصنيف موضوعي
        ↓
تضمينات multilingual-e5 محلية → Qdrant + SQLite FTS5
        ↓
بحث هجين (دلالي + كلمات مفتاحية) مع أولوية النسخة الأحدث
        ↓
Gemini المجاني عند الإعداد أو Ollama المحلي
        ↓
إجابة باللغة نفسها + إحالات مصدرية أو امتناع عند غياب الدليل
```

تخزن المحادثة محلياً لدعم أسئلة المتابعة. تُرسل إلى مزود التوليد مقتطفات الاسترجاع والسياق السابق فقط، لذلك استخدموا بيانات عامة أو مصرحاً بها، وراجعوا شروط المزود المختار. تبقى المحادثات والبيانات الوصفية في SQLite، والمتجهات في Qdrant المحلي افتراضياً. يدمج الاسترجاع النتائج الدلالية مع FTS5 باستخدام ترتيب RRF؛ يضبط `RETRIEVAL_CANDIDATE_LIMIT` عدد المرشحين الأوليين لكل مسار، مع إضافة أدلة النسخ الأحدث ومرشحي الكلمات المفتاحية اللازمة قبل الاختيار النهائي.

## التحقق

```powershell
uv run pytest
uv run ruff check .
uv run ruff format --check .
uv lock --check
uv run rag-aaup index
uv run python scripts/evaluate_retrieval.py
```

تختبر `data/eval/aaup_questions.jsonl` استرجاع المصادر والصفحات من مستندات AAUP الرسمية. ملف PDF الرسمي مستثنى من Git؛ لذلك يتخطى التقييم حالاته حتى يُضاف محلياً إلى `data/raw/`. يقيس السكربت استرجاع الأدلة فقط، ولا يصادق على دقة الإجابة المولدة أو الامتناع. راجعوا صحة الاسترجاع والاستشهاد والامتناع قبل العرض.

تحقق ترحيل Qdrant بتاريخ **2026-11-07**: نجحت الاختبارات الآلية **22/22**، وتقييم الاسترجاع **7/7 دون تخطٍ** على المستندين المحليين، بما فيهما PDF الرسمي. رُحّلت **61 متجهة بأبعاد 384** دون إعادة التضمين. نجحت فحوص Ruff والتنسيق وقفل الاعتماديات، وفحص HTTP حي للصحة وقائمة المستندات وإعادة الفهرسة والصفحة الرئيسية، ثم إعادة فتح Qdrant بعد إغلاق الخادم. لا يشمل ذلك التحقق من مزود LLM أو من خادم Qdrant خارجي.

بعد إصلاح إعداد التوليد والإرسال المتكرر في اليوم نفسه، نجحت **29 حالة اختبار**، بما فيها تفعيل مفتاح أثناء التشغيل عبر مزود محاكى، والبحث المتكرر دون LLM، والتعافي بعد فشل التوليد. جرى أيضاً اختبار طلبَي بحث HTTP فعليين، ومنطق الواجهة لمنع الإرسال المكرر واستعادة الزر بعد الخطأ والمهلة. يبقى اختبار Gemini الحقيقي معتمداً على إضافة مفتاح صالح.

## الشجرة

```text
src/rag_aaup/
  ingestion/    استخراج المستندات
  processing/   تطبيع النص والتقطيع وتصنيف الموضوع
  indexing/     التضمينات وQdrant وSQLite / FTS5 والفهرسة المتزايدة
  retrieval/    الاسترجاع الهجين وإصدارات المستند
  generation/   مزودات التوليد وسياسة الالتزام بالمصادر
  web/          واجهة المستندات والأسئلة وحالة الفهرسة
  api.py        واجهة الويب وREST API
  assistant.py  إدارة السؤال والمحادثة
  cli.py        أوامر serve وindex
data/raw/       مستندات محلية، مستثناة من Git
documents/      ملفات الشركة، مستثناة من Git
data/eval/      أسئلة التقييم
indexes/        قاعدة البيانات والفهارس المحلية، مستثناة من Git
tests/          اختبارات آلية
problem/        مواد المسابقة المحلية؛ لا تُرفع تلقائياً
```

## استخدام أدوات الذكاء الاصطناعي
