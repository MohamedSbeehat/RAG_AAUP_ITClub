# المرشد الأكاديمي الذكي — AAUP RAG

مساعد أكاديمي عربي/إنجليزي للقبول والتسجيل، مبني على استرجاع المعلومات من مستندات الجامعة. يهدف هذا المشروع إلى إجابات مرتبطة بمصدر قابل للتحقق، لا إلى توليد سياسات جامعية من الذاكرة.

> **تنبيه:** لا تضعوا بيانات شخصية أو ملفات سرية في النظام. ملف الاختبار المرفق مُلخّص من مصادر AAUP الرسمية، وليس لائحة رسمية. المستندات التي تصلح للمسابقة يجب أن تأتي من اللجنة أو من مصدر عام موثوق، مع توثيق المصدر.

## المتطلبات

- Windows 10/11 أو Linux.
- Python 3.13 (الإصدار المحدد في `.python-version`).
- `uv` لإدارة بيئة المشروع.
- مساحة قرص لتنزيل نموذج التضمين متعدد اللغات أول مرة. يعمل التضمين محلياً؛ لا يحتاج مفتاح API.
- لتوليد الإجابات: مفتاح Gemini من الخطة المجانية، أو Ollama مع نموذج محلي. حدود الخطط المجانية وتوفرها تتغير؛ Ollama لا يحتاج API key لكنه يحتاج تنزيل النموذج.

## التثبيت والتشغيل على Windows

```powershell
winget install --id astral-sh.uv
uv sync --group dev
Copy-Item .env.example .env
uv run rag-aaup serve
```

افتح <http://127.0.0.1:8000>. تُتاح واجهة API التفاعلية على <http://127.0.0.1:8000/docs>.

### إعداد توليد الإجابات المجاني

**Gemini (اختياري):** أنشئ مفتاحاً من Google AI Studio وأضفه إلى `.env` في `GEMINI_API_KEY`. لا تضع المفتاح في GitHub أو في الواجهة الأمامية.

**Ollama المحلي (بدون مفتاح):**

```powershell
winget install --id Ollama.Ollama
ollama pull qwen2.5:3b
```

عند `LLM_PROVIDER=auto` يحاول النظام Gemini عند وجود مفتاح، ثم Ollama عند فشل خدمة Gemini. إذا لم يكن أي مزود متاحاً، يرجع النظام خطأ واضحاً بدلاً من إجابة وهمية. ويمكن ضبط `LLM_PROVIDER` إلى `gemini` أو `ollama`.

## إضافة المستندات وتحديثها

انسخ ملفات الجامعة إلى `data/raw/`، أو ارفعها عبر واجهة `/docs` باستخدام `POST /api/documents`. الأنواع الحالية: PDF النصي، DOCX، XLSX، TXT، وMarkdown. ملفات PDF المصوّرة التي لا تحتوي طبقة نص تحتاج OCR، وهو غير مفعّل في هذه النسخة.

يتضمن المستودع ملف اختبار واحداً [AAUP_Official_Test_Corpus_2026-11-07.md](./data/raw/AAUP_Official_Test_Corpus_2026-11-07.md)، وهو ملخص مُعاد الصياغة من لوائح وصفحات AAUP الرسمية مع روابط المصادر وتاريخ التحقق. كما تم تنزيل نسخة PDF الرسمية محلياً للاختبار، لكنها مستثناة من Git؛ لا يُرفع ملف المصدر الأصلي دون مراجعة حقوق النشر وسياسة اللجنة.

يفحص التطبيق مجلد `data/raw/` عند التشغيل، بعد الرفع، وكل 45 ثانية افتراضياً. ويمكن فرض فحص فوري:

```powershell
uv run rag-aaup index
```

يخزن SQLite بصمة كل ملف ومقاطع النص والتضمينات وفهرس FTS5. الملفات التي لم تتغير لا يعاد تضمينها؛ والملف المحدّث يعاد فهرسته. لا تُرفع المستندات أو التضمينات إلى خدمة التوليد.

### نسخ المستندات

احتفظوا بنسخ السياسات ولا تستبدلوا الأقدم عند إضافة إصدار جديد. استخدموا اسماً ثابتاً مع سنة أو رقم إصدار في النهاية، مثل:

```text
data/raw/Student_Guide_2025.pdf
data/raw/Student_Guide_2026.pdf
```

تُجمع النسخ ذات الاسم الأساسي نفسه، وتُفضّل النسخة ذات السنة/رقم الإصدار الأعلى. عند عدم توفر مقطع ملائم في النسخة الأحدث، يمكن الاسترجاع من النسخ الأقدم وتظهر بوضوح في المصدر على أنها مرجع احتياطي. للمستندات التي تحمل أسماء غير متسقة، وحّدوا الاسم الأساسي قبل الفهرسة؛ لا يُستنتج تطابق النسخ من تشابه محتواها.

## كيف يعمل

```text
PDF / DOCX / XLSX / TXT / Markdown
        ↓
استخراج النص والصفحة أو القسم
        ↓
تقطيع متداخل + تصنيف موضوعي
        ↓
تضمينات multilingual-e5 محلية + SQLite FTS5
        ↓
بحث هجين (دلالي + كلمات مفتاحية) مع أولوية النسخة الأحدث
        ↓
Gemini المجاني عند الإعداد أو Ollama المحلي
        ↓
إجابة باللغة نفسها + إحالات مصدرية أو امتناع عند غياب الدليل
```

تخزن المحادثة محلياً لدعم أسئلة المتابعة. تُرسل إلى مزود التوليد مقتطفات الاسترجاع والسياق السابق فقط، لذلك استخدموا بيانات عامة أو مصرحاً بها، وراجعوا شروط المزود المختار. تبقى فهارس المستندات ومحادثاتها على الجهاز في SQLite.

## التحقق

```powershell
uv run pytest
uv run ruff check .
uv run rag-aaup index
uv run python scripts/evaluate_retrieval.py
```

تختبر `data/eval/aaup_questions.jsonl` استرجاع المصادر والصفحات من مستندات AAUP الرسمية. ملف PDF الرسمي مستثنى من Git؛ لذلك يتخطى التقييم حالاته حتى يُضاف محلياً إلى `data/raw/`. يقيس السكربت استرجاع الأدلة فقط، ولا يصادق على دقة الإجابة المولدة أو الامتناع. راجعوا صحة الاسترجاع والاستشهاد والامتناع قبل العرض.

## الشجرة

```text
src/rag_aaup/
  ingestion/    استخراج المستندات
  processing/   تطبيع النص والتقطيع وتصنيف الموضوع
  indexing/     التضمينات وSQLite / FTS5 والفهرسة المتزايدة
  retrieval/    الاسترجاع الهجين وإصدارات المستند
  generation/   مزودات التوليد وسياسة الالتزام بالمصادر
  api.py        واجهة الويب وREST API
  assistant.py  إدارة السؤال والمحادثة
  cli.py        أوامر serve وindex
data/raw/       مستندات محلية، مستثناة من Git
data/eval/      أسئلة التقييم
indexes/        قاعدة البيانات والفهارس المحلية، مستثناة من Git
tests/          اختبارات آلية
problem/        مواد المسابقة المحلية؛ لا تُرفع تلقائياً
```

## استخدام أدوات الذكاء الاصطناعي

يُستكمل هذا القسم بأسماء الأدوات الفعلية المستخدمة في تطوير النسخة النهائية، وبما يتوافق مع إفصاح المسابقة. يجب على أعضاء الفريق فهم الكود ومراجعة كل إجابة ومصدر قبل العرض.
